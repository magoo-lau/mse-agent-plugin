## 7. 数据库与中间件约定

- 业务主库默认 `mse_tenant`（缺省共享租户库，MSE_TENANT_DB 可覆盖，首启自动建库）；租户库由「租户数据源」界面维护（可建 `mse_tenant_<n>`）。
- 达梦：库映射为 schema（平台库对应 schema `MSE`，默认端口 5236）；金仓：独立 database + 同名 schema（库名 `mse`，MSE_KB_DB 可覆盖，默认端口 54321）。
- Nacos：`localhost:8848`（控制台 18080），Group=DEFAULT_GROUP；共享配置 `mse-micro-common/db/dubbo.yaml` 勿动。
- 子应用部署路径：`/sub-apps/<biz>/`；基座路由前缀 `/sub/<biz>/**`。
- **移动端部署（2026-09-27）**：移动基站 mse-ui-mobile 部署于 `/m/`（构建 base=/m/，dev 端口 3200）；移动子应用部署于 `/m-apps/<biz>/`（构建 base=/m-apps/<biz>/）；移动子应用路由前缀仍为 `/sub/<name>`（urlPrefix 契约与 PC 一致，子应用模板零改动）。移动端子应用须在 sys_micro_app 登记 `client=2`，页面菜单 client=2（PC/移动端入口分离授权，权限点双端共享）。
- **业务 SQL 为 jar 内 `db/<方言>/` 版本化迁移脚本（免手工执行，头指令 -- mse-target 区分目标）**：`V…_<biz>__base.sql`（mse-target: base）目标=租户域 base（租户库车队自持：共享主库+各独立租户库，starter-bridge 推送 mse-system 按各库账本重放），`V…_<biz>__init.sql`（mse-target: master，缺省）目标=业务主库+租户独立库（业务表，auto-migrate 随启动应用）；脚本幂等，重复应用/推送无害。历史手工方式（工程级 `sql/<方言>/` 的 base/init 脚本）已废弃。

## 10. 脚本归属指引（0.1.0 目录真源上收后的增量约定）

- **平台端菜单（menu_scope=1）应走 `-- mse-base-scope: platform` 脚本**（落平台库）：现存反例——
  mse-im 的 `V20261001_01_im__im_base.sql` 里菜单 519/520（menu_scope=1）走的是缺省租户域 base 通道
  （落各租户库副本）。已应用脚本不改（checksum 纪律）；新工程的平台端菜单一律 platform 域。
- **租户域 base 脚本的双路分发是自动的**（平台库目录摄入 + 登记库车队重放），biz 开发者零感知、
  写法不变；平台端对目录的运行期编辑经 `sys_catalog_change` 批次扇出，不要在 biz 脚本里覆盖
  （NOT EXISTS 见行即跳——编辑不被脚本重置）。
- **缺省共享库不再是静态数据源**：`mse-micro-db-biz.yaml` 只声明 platform；内置共享库经各服务
  `mse.tenant.shared-main.*` 自declare 注册（键默认=本服务应用名，不落登记表），其他共享库/独立库经
  「租户数据源」界面登记。
